# IPv6のみの上流DNSが選ばれた場合のIPv4 DNSへの切替仕様

[インストールと機能](../README.md) · [技術資料一覧](README.md)

決定日：2026-09-23。**本資料はv0.9.9に実装した仕様です。v0.1.4・NVR試験版v0.1.4-nvr.1の配布ファイルには含まれません。** YAMAHA RTX830・YAMAHA RTX1210でネイティブLuaの解析試験と機能回帰を確認しました。[v0.9.9の解説](releases/v0.9.9.md)と[検証記録](validation.md#v099-validation)に範囲を記載します。負荷試験は別に記録します。

## 決定した3条件

1. IPv6のみで利用できない規則を除外し、条件に合う後続のselect規則を探す。
2. 見つからなければ、通常の `dns server` に利用可能なIPv4があれば使う。
3. それでも問い合わせできなければSERVFAIL。

この処理は、上流DNSとの通信がIPv4に限られるLuaスクリプトのための拡張です。YAMAHAルーターの内蔵DNSがIPv6を使えないという意味ではありません。また、IPv6／IPv4はDNSサーバーへの接続先アドレスの話であり、AAAAレコードもIPv4経由で問い合わせできます。

## 選択の流れと例外

`dns server select`を番号の小さい順に調べ、問い合わせ名・レコード種別・送信元IPv4・`restrict pp`の条件を評価します。同じ規則に利用可能なIPv4候補が含まれる場合は、その規則のIPv4を使います。

読み飛ばすのは、設定・適用条件・取得状態・候補アドレスを正常に解釈でき、利用できない理由が「DNSサーバーのアドレスがIPv6のみ」と確定した規則だけです。後続の規則にも同じ条件判定を行います。

| 調べた規則・状態 | 処理 |
|---|---|
| 問い合わせ条件に一致しない | 次のselect規則を調べる |
| `restrict pp`の対象が明確にDOWN | 条件不一致として次のselect規則を調べる |
| 一致し、同じ規則に利用可能なIPv4がある | その規則のIPv4を使う |
| 一致し、利用できない理由がIPv6のみ | 次のselect規則を調べる |
| DNS取得状態・取得元・選択条件が不明 | 対象となり得る問い合わせを、その規則でSERVFAILにする。後続や通常DNSへ送らない |
| NAT46が必要、未知のオプション、不正な取得アドレス等 | IPv6のみと同一視せず、該当する問い合わせをSERVFAILにする |
| 解釈できる明示的な`reject`に一致 | 従来どおり問い合わせを破棄する。後続や通常DNSへ送らない |
| 後続selectを調べ終わり、通常DNSに利用可能なIPv4がある | 通常DNSのIPv4を使う |
| 利用可能な宛先がない、または選んだ宛先での処理が最終的に失敗 | SERVFAIL（RCODE=2）を返す |

先行するIPv6のみの規則を除外していても、途中で判定不能な規則や明示的な拒否に当たったら、その処理を優先します。「後続のIPv4を探す」ことを理由に、これらの規則を読み飛ばしません。

通常DNSは、固定の`dns server`、`dns server pp`、NVRの`dns server pdp`、`dns server dhcp`の優先順で決まる設定を使います。PDPからのDNS取得は未対応なので、PDPが選ばれた問い合わせはSERVFAILです。今回追加するのは、その通常設定へ進む条件です。通常の固定DNSがIPv6のみであることを理由に、さらに通常PP・DHCPへ切り替える処理は追加しません。[DNS選択仕様](dns-policy.md)

## 設定例

以下は選択順序を説明するための例です。アドレスは文書用であり、実際に問い合わせるDNSのアドレスではありません。

```text
dns server select 10 2001:db8::53 any .
dns server select 20 192.0.2.53 any example.test
dns server 198.51.100.53
```

| 問い合わせ | この仕様での選択 |
|---|---|
| `www.example.test A` | 規則10はIPv6のみなので除外し、条件に合う規則20の`192.0.2.53`を使う |
| `www.other.test A` | 規則10を除外し、規則20には一致しないため、通常DNSの`198.51.100.53`を使う |
| `www.example.test AAAA` | 規則20の`192.0.2.53`へIPv4 TCPでAAAAレコードを問い合わせる |

PP・DHCPで取得したDNSにも同じ考え方を適用します。例えば、先行するDHCP取得規則のDNSがIPv6のみで、後続のPP取得規則が条件に一致しIPv4 DNSを持つ場合は、そのPP取得DNSを使います。

## 切替の対象にしないもの

IPv6のDNSアドレスを取得済みである状態は「DNS未取得」ではありません。select行内の代替IP（公式構文の`default-server`）を使う条件は、従来の明確な未取得時のままとし、今回の変更では拡張しません。

IPv4の宛先を選べることと、その宛先と通信できることも別です。接続拒否・タイムアウト時の再試行は、従来どおり選択した規則内で行います。通信障害を理由に後続select規則や別の通常DNS設定へ選択をやり直す機能は追加しません。

この拡張は外部上流へのTCP問い合わせに適用します。YAMAHAルーターに登録した簡易DNSレコードを内蔵DNSへ問い合わせる処理、通常のUDP問い合わせ、アクセス許可、config変更後のスクリプト再起動という運用は維持します。

## ヤマハ標準の選択動作との関係

ヤマハ公式マニュアルでは、select規則は番号順に調べ、一度条件に一致したら後続を検索せず、どの規則にも一致しない場合は他のDNS設定を使うと説明されています。したがって、通常の`dns server`はselect非一致時の選択先です。[公式：dns server select](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/dns/dns_server_select.html)

本仕様は、この「非一致時の通常DNS利用」に加え、Luaでは通信できないことが確定したIPv6のみの規則を除外した場合にも、後続規則や通常DNSを候補とする拡張です。内蔵DNSの挙動と同一であるとはしていません。DNS設定コマンド全体の優先順位は[公式のDNS設定説明](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/dns/dns_chapter.html)を参照してください。

異なるDNSへ問い合わせるため、内蔵DNSがIPv6側のDNSを使う場合と、LuaがIPv4側のDNSを使う場合とで、回答やフィルタリング結果が異なることがあります。独自の名前を解決するDNSや、ISPごとに回答の異なる構成では、この点も検証します。

## 実装・検証状況

現行NVR試験版と[PR #1](https://github.com/Yamar50/rtx-dns-tcp-lua/pull/1)について、設定・状態表示・ソケットを疑似化した28条件×2版の比較を行いました。実際の設定解析・DNSメッセージ処理・リレー処理を用い、IPv6のみの先行規則に一致した場合、現行NVR試験版はSERVFAIL、PR版は後続PP IPv4へ進んでA・AAAA・TXTの応答を取得することを確認しました。実回線・実機による検証とは区別しています。

PRは利用不能の理由を広く読み飛ばし、後続に利用可能なselect規則がなければ、最初の利用不能規則を返します。本資料の「IPv6のみの場合に限定する」「通常DNSまで候補にする」という仕様とは異なります。PRの動作確認を、本仕様の実装・検証完了とはしていません。

v0.9.9には、利用不能の理由を区別し、IPv6のみの場合だけ後続selectと通常DNSへ進む処理を実装しています。`tests/test_ipv6_fallback.lua`などで、選択順序、通常DNSへの継続、判定不能・拒否の維持、同じ規則のIPv4利用、動的DNSの変更・復帰を確認する回帰試験を追加しました。YAMAHA RTX830・YAMAHA RTX1210では、これらの合成データによる試験を実際のLua環境で実行し、別ポートの実ソケットでDNSリレーの機能回帰も確認しました。実際のIPv6回線・DHCPv6取得・IPoEとPPPoEの併用回線による通信の検証とは区別します。[確認した版と範囲](validation.md#v099-validation)
