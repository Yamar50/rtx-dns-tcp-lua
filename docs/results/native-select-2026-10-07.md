# 内蔵DNSのselect選択とPP・DHCP状態の比較記録

試験日：2026-10-07。内蔵DNSの実機挙動と、**変更していないv1.0.0ソースによる状態解析・選択**を分けて記録します。修正版の合格報告ではありません。

## 試験条件

| 項目 | 条件 |
|---|---|
| 実機 | RTX1210 Rev.14.01.42、2台。1台を内蔵DNSの評価対象、もう1台をPP／DHCPの補助として使用 |
| 評価対象 | 内蔵UDP/53。評価対象ルーターにLua中継は未導入 |
| PP | LAN内のPPTP接続とIPCP DNS通知。商用PPPoE回線ではない |
| DHCP | 直結LANに試験用IPv4 DHCP。評価対象の別のDHCPインターフェースは維持 |
| 問い合わせ | 各条件で未使用名のA要求1件。内蔵キャッシュ無効、UDP指定、自動TCP切替なし、EDNSなし、クライアント再試行なし |
| 無応答の観測 | クライアント待ち時間45秒と、その後の記録回収。無制限の時間に対する結論ではない |
| 送信先の確認 | 合成DNSの受信記録と、ルーターの宛先別通過ログ。各経路の正常応答の対照も実施 |
| 完了した問い合わせ | 固定設定・未使用PPの14件、接続したPPの8件、`restrict`なしの追加4件、DHCPの9件、計35件。正常対照・繰り返しを含み、35種類の独立した仕様を検証した意味ではない |
| Lua比較 | v1.0.0の`dns_runtime.lua`・`dns_policy.lua`等。実機表示のUTF-8／CP932再生とソース読解。実機上のLua TCP比較ではない |

比較に使用したソースの作業基準commitは`9a56899cca8a0a2c743b4fbdadb1dde00046cef1`です。`src/dns_runtime.lua`・`src/dns_policy.lua`・`src/relay.lua`はv1.0.0タグと差分がないことを確認しています。配布物や制限値は変更していません。

## 内蔵DNSで観測したこと

| 観測ID | 状態・条件 | 実測結果 |
|---|---|---|
| N01 | 一致した固定IPv4 DNSがSERVFAIL／無応答。後続selectと通常DNSも設定 | SERVFAILを返すか、45秒のクライアントタイムアウト。後続select・通常DNSへの要求を観測しなかった。先行規則がタイプ不一致で次の規則を選ぶ対照も確認 |
| N02 | PP接続済み、IPCPでDNS取得済み | 当該PPのDNSで正常応答。SERVFAIL／無応答にしても、後続select・通常DNSへ進まなかった。`restrict`あり／なしで確認 |
| N03 | `pp disable`と`disconnect`で非接続、`restrict pp`あり | その規則を使わず後続selectで正常応答。別の対照では、固定DNSを参照する規則でも未使用PPへの`restrict`によって後続へ進むことを確認 |
| N04 | 同じ非接続状態、`restrict`なし | 後続select・通常DNSを使わずクライアントタイムアウト |
| N05 | PP接続済み、IPCPからDNS通知なし | `restrict`あり／なしとも後続select・通常DNSを使わずタイムアウト。行内の代替DNSを指定した試験でも、その代替DNSへの要求を観測しなかった |
| N06 | DHCPリースとDNS取得済み。取得元LANを管理的にshutdown | IPリースとDNSを保持。当該取得DNSに別のLAN経路で問い合わせ、期待した合成A応答を取得 |
| N07 | shutdown中にIP設定を解除・DHCPへ再設定し、IP欄が「サーバ検索中」。行内代替DNSなし | 後続selectではなく、通常の固定DNSへの問い合わせと応答を観測 |
| N08 | N07と同じ状態で、行内の代替DNSを指定 | 行内代替DNSでも後続selectでもなく、通常の固定DNSへの問い合わせと応答を観測 |

N06では、取得DNSを別経路で使えるように試験用の戻り経路を設定しています。リンクダウンした元の経路で通信できたという結果ではありません。N07・N08は**IPリースを取得していない状態**であり、IP取得済みでDNSオプションだけがない状態とは区別します。

N05・N08は、未取得時の代替DNSに関する公式説明だけでは今回の結果を説明できないため、状態・機種・FW差の追加確認が必要です。「行内の代替DNSはすべて無効」と一般化しません。[公式：dns server select](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/dns/dns_server_select.html)

## Luaソースとの照合

| 実機から採取した情報 | v1.0.0のオフライン再生結果 |
|---|---|
| PPの「PPTPセッションは接続されています」 | 接続状態を認識できず`unknown` |
| PPの「回線は現在使用できません」 | 非接続と認識できず`unknown`。`restrict`を確定できないため、対応規則は利用不可 |
| DHCPの「サーバ検索中」 | IPv4 DHCP状態全体を解析できず`unknown` |
| 2つのDHCP取得インターフェースと共通DNS欄 | `IPv4 DHCP source is ambiguous`。既存の取得元特定に関する制約であり、今回新しく追加した判定ではない |

上記の`unknown`からSERVFAILになることはリレーソースで確認しています。実機上のLuaに同じ設定を入れた通信試験としては数えません。

切り分け用に、採取したDHCP表示の「サーバ検索中」だけを、現行実装が認識する「未取得」に置き換えた再生も行いました。行内代替DNSなしなら通常DNS、代替ありならその代替DNSを選びました。これは**合成入力による解析経路の確認**であり、ファームウェアがその表示を返した証拠でも、修正後の実機結果でもありません。

## 未実施・結論の範囲

- DHCPの計画したリンク復帰後の比較ケースは、シリアルへの再ログインがタイムアウトして実施できませんでした。終了処理では再接続でき、復元できています。
- PPの試験はPPTP/IPCPです。PPPoE、RTX1300の報告環境、全機種・全FWの確認ではありません。報告者環境の障害原因は未確定です。
- LAN切断は管理的shutdownです。物理ケーブル切断、自然なリース期限切れ、IP取得済みでDNS通知なし、DHCPv6、ONU等は未確認です。
- 同じselect規則内の複数DNS候補の再試行や、通常DNS設定同士の取得不能時の優先順位を網羅した試験ではありません。
- 準備段階の戻り経路不足・観測処理の失敗・DHCP未取得による未成立試験は、上記35件の結論に含めません。DHCPの途中中断は全項目合格とは扱いません。

## 復元確認

両ルーターの試験用設定を除去し、試験前のconfig、ファイル一覧、Luaタスクのコマンド、起動情報に戻ったことを確認しました。保存configのメタデータは不変で、試験中に`save`は行っていません。保存config本文の検証を行ったという意味ではありません。

試験用DNSプロセスと一時ホスト経路は削除済みです。終了時には、常用Luaを保持した補助ルーターでTCP DNS、評価対象で内蔵UDP DNSの正常応答を確認しました。これらは終了時点の観測であり、その後の稼働保証ではありません。
