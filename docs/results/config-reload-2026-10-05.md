## 対象と結論

RTX1210 Rev.14.01.42（整数版Lua 5.1.5、Lua機能版1.08）で、v1.0.0に採用する自動再読込処理を検証しました。12項目の機能試験と、約141.5時間にわたる設定変更・問い合わせの連続試験で、安定状態の想定外の結果は0件でした。試験終了後は元のDNS設定・Lua稼働状態へ戻し、試験用ファイルと一時認証ファイルを削除しました。

連続試験は当初7日間を予定しましたが、v1.0.0公開に進む指示を受け、2026年10月5日に終了しました。**7日間完走の結果ではありません。**

総数には、設定の反映待ちの時間帯と、意図的に問い合わせを拒否・DNSを無効にした時間帯を含みます。「想定どおり」には、試験設定に応じた回答・切断・無応答を含み、全件が正常なDNS回答だったという意味ではありません。設定反映中の結果を成功率へ算入していません。

Luaヒープは観測値で、ルーター全体のメモリ使用量や未観測の瞬間最大値を示しません。試験制御では起動時刻・Luaタスク・記録の更新を確認し、試験期間中にルーター再起動や想定外のタスク喪失を検出しませんでした。

## 確認した12項目

| 項目 | 確認内容 |
|---|---|
| 通常DNSの変更 | 固定IPv4上流への切替 |
| 簡易DNS登録の追加 | 新しい登録名の回答 |
| 簡易DNS登録の変更 | 変更後の回答、古いキャッシュの破棄 |
| 簡易DNS登録の削除 | 旧登録を使い続けないこと |
| selectの明示拒否 | 指定された問い合わせを転送しないこと |
| selectの転送設定 | 指定上流への転送 |
| selectの削除 | 通常DNSへ戻ること |
| アクセス許可の縮小 | 既存接続を含む旧許可の終了 |
| アクセス許可の復旧 | 同じLuaタスクでの自動復帰 |
| DNSサービスの無効化 | 待受停止 |
| DNSサービスの復旧 | 再待受と回答 |
| 設定が変わらない場合 | 初期化を繰り返さず接続・キャッシュを保持 |

新しいTCP接続と継続使用する接続を交互に使用しました。各設定の反映を待った後に、その設定で期待される結果を検証しました。通常配布版と同じ接続数・送信元ごとの問い合わせ数制限を維持しており、限界負荷試験ではありません。

## 試験用ファイルと公開ファイルの区別

上の実機試験は、記録出力を追加した試験用ファイル（162,510バイト、SHA256 `a3ba9e1057fde7701291f53559a5a51ee3ad70c4477aa4aaa03f55df126d3c06`）の結果です。公開ファイルには試験用の送信先や記録用処理を含めません。自動再読込の実装は共通ですが、試験用ファイルとv1.0.0配布ファイルを同一ファイルとして扱いません。

公開用ファイルの生成・回帰試験と最終確認は、[v1.0.0の詳細](../releases/v1.0.0-details.md)に記録します。他機種で自動再読込を確認した結果として、このRTX1210の試験を扱いません。

## バージョン固定オンラインインストーラーの確認（10月5日）

同じRTX1210で、公開commitに固定したv1.0.0インストーラーをコンソールから`no`指定で実行しました。自動起動設定や保存済みconfigを変更しないモードです。

- `1/16`から`16/16`までの表示と完了を確認。
- 本体のSHA256・構文検査、インストール後の全バイト読み戻し一致、単一Luaタスクの稼働を確認。
- AのTCP回答と、`microsoft.com TXT`のTCP回答（4,633バイト、59回答、TCなし）を取得。
- 実際の`dig`でUDPの切り詰め後にTCPへ自動切替し、NOERRORの回答（4,644バイト）を取得。直接TCPの試験との11バイト差はOPTレコードの有無によるもの。
- 試験は60.43秒で終了。作成したファイル・タスクを削除・停止し、元の稼働設定・保存設定のメタデータ・起動時刻が一致したことを確認。

このv1.0.0の最終試験はコンソールからの`no`指定です。`yes`指定の自動起動・保存やWebGUI操作の過去版の実機結果は、それぞれの[既存の検証記録](versioned-installer-2026-09-25.md)・[WebGUI検証記録](webgui-uninstaller-2026-09-25.md)として区別しています。
