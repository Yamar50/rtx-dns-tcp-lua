# PPPoE状態の英語表示と解析の確認

[既知の問題](../known-issues.md) · [内蔵DNSとの互換性計画](../dns-select-native-compatibility.md)

ソースコード・テスト・ドキュメントはすべてOpenAI Codexで生成した。

試験日：2026-10-07。**実機からの状態文の採取と、ホスト上での解析試験です。修正版による実機DNS通信やRTX1300の問題解消を確認したものではありません。**

## 実機で採取した表記

接続済みのRTX830 Rev.15.02.33ではPPPoEを切断せずに確認しました。RTX1210 Rev.14.01.42では未使用のPPを一時設定し、接続処理中と切断後の表示を採取しました。いずれも`PP[01]:`の出力です。

| 機種・状態 | 英語の状態文 |
|---|---|
| RTX830・接続中 | `Current PPPoE session status is Connected.` |
| RTX1210・PP未設定 | `Current line status is disabled.` |
| RTX1210・未接続 | `Current PPPoE session status is Offline, never connected.` |
| RTX1210・接続処理中 | `Current PPPoE session status is In connecting process.` |
| RTX1210・切断後 | `Current PPPoE session status is Offline.` |
| RTX1210・PP無効化 | `Current PPPoE session status is disabled.` |

RTX830の接続中表記は、RTX1300 Rev.23.00.20の協力者から提供されたコンソール表示と同じでした。表示の提供に感謝します。RTX1300をこちらで操作・再検証したという意味ではありません。

## コンソールとLuaの表示言語

今回の機器は元の設定が`console character ja.utf8`でした。SSHコンソールだけを一時的に`en.ascii`へ変更すると、コンソールは英語でも、新しく起動したLuaの`rt.command()`は日本語CP932を返しました。同じLuaタスク内で`rt.command("console character en.ascii", "off")`を実行してから状態を読むと、上表の英語が返ることを確認しました。

このため、コンソール画面の言語だけで稼働中のLuaが受け取る言語を断定しません。保存設定・起動経路による言語の継承条件を網羅した試験ではありません。本体スクリプトに表示言語を強制変更する処理は追加していません。

## 解析結果と修正候補

比較元はv1.0.0と同じ状態解析を持つcommit `7372ba549c6c93731b54d9ed39d2e7567e82842a`です。採取したLuaの生バイト列を、ホストのLua 5.4.7で修正前後の解析器に入力しました。

| 入力 | 修正前 | ローカル修正候補 |
|---|---|---|
| 接続中の日本語CP932（2回採取） | 接続中・DNSを2件取得 | 同じ結果 |
| 接続中の実際の英語 | `unknown`、DNS候補なし | 接続中・DNSを2件取得 |
| 上表の英語の非接続・接続処理中（5種類） | `unknown` | 引き続き`unknown`。対応は未実装 |

既存実装が想定していた`PPPoE session is connected`とは文が異なるため、実際の接続中の英語表記を認識対象へ追加しました。文全体を正規化して照合し、説明欄・別のプロトコル・`Not connected`等から接続中と誤認しない扱いを維持します。DNSサーバーの選択順序やエラー時の後続規則への切替は変更していません。

修正候補の`src/dns_runtime.lua`のSHA-256：`e6599290557833f739788921a27956a8778949f9a06130b9a671e420d32a5645`。

ホスト上では状態解析700、動的DNS選択259、DNSポリシー497、IPv6例外618、NVR互換273、設定再読込157チェックと、リレー72試験が成功しました。報告者の3規則を模した合成入力で、接続中は規則2、既知の切断表示では規則3、状態不明では規則2の利用不可を確認しています。これは実ネットワークの問い合わせ結果ではありません。

## 復元と未確認範囲

両機とも試験前後の実行中設定、保存設定の一覧情報、起動時刻、稼働Luaを照合して復元を確認しました。RTX1210のファイル一覧も不変です。`save`、本体スクリプトの配備、他のDNS設定の変更は行っていません。RTX830のPPPoEは接続を維持しています。保存config本文の比較は行っていません。

今回の結果で確定したのは、実際の英語表示に対する解析の不足です。RTX1300の稼働Luaが受け取った生の状態文と、修正版によるDNS応答はまだ未確認です。PP非接続・接続処理中の扱い、PPTP/L2TP、DHCPの状態別互換性は[別途の計画](../dns-select-native-compatibility.md)に残ります。公開済みv1.0.0の配布物は変更していません。
