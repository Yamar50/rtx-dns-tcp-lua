## 動作確認の範囲

- **開発時の実機検証**：RTX830・RTX1210は整数版Lua 5.1.5、Lua機能版1.08です。[v0.1.4の検証結果](validation.md#v014-validation)に試験内容を記録しています。過去の負荷測定は、その測定に使ったスクリプトの版と条件に限った結果です。
- **協力者の報告**：RTX1300の報告はv0.1.2に対するものです。試験項目とLuaの版は未確認です。
- **NVR510の報告**：2026-09-23、協力者から[配布試験版v0.1.4-nvr.1](https://github.com/Yamar50/rtx-dns-tcp-lua/releases/tag/v0.1.4-nvr.1)に[PR #1の修正](https://github.com/Yamar50/rtx-dns-tcp-lua/pull/1)を加えた版の動作報告がありました。外部A、大型TXT（4,564バイト・58レコード）、内蔵DNSの登録名をTCPで取得できたとのことです。[報告ポスト](https://x.com/shigehiro/status/2102724584185500116)。追加修正は、利用できない選択規則から後続の利用可能な規則へ進む処理です。表の確認対象はこの修正版であり、追加修正前の配布ファイルではありません。PRの採否は別途確認します。

NVR510については、続く[追加報告](https://x.com/shigehiro/status/2102725908398518745)で、IPv6とIPv4を別経路で利用する環境でも動作し、スケジュール登録して利用する意向が示されています。PR本文ではONU側のIPv6 DNSとPP1側のIPv4 DNSを併用しています。この構成を「一般的」とは位置付けず、報告者の環境での結果として記録します。スケジュール登録後の実再起動による自動起動確認は、今回の報告には含まれていません。

NVR700Wの`dns server pdp wan1`によるDNS取得は、現在のスクリプトでは未対応です。

## 実行環境の条件

現在のスクリプトは、YAMAHA組み込みのLuaと`rt.socket`を使います。外部のLuaSocketや追加ライブラリのインストールは不要です。

必要なAPIには、TCP/UDPソケット、`select`、`gettime`、`rt.command`、`rt.sleep`、`rt.syslog`が含まれます。LuaSocketはLua機能版1.06、`rt.command`のログ抑制引数は1.07で追加されています。表の最低版は両方を満たす版です。vRXの一部旧版は例外があるため、Lua機能版の数字だけでLuaSocketの存在を判断しません。[ヤマハ公式API仕様](https://www.rtpro.yamaha.co.jp/RT/docs/lua/rt_api.html)

ルーターの機種名を列挙して起動を許可する方式ではありません。表にない機種も、必要なAPIと設定の条件が確認できれば追記します。スイッチ製品は対象外です。通信はIPv4経由で、AAAAレコードの問い合わせとIPv6による通信は区別します。

SRT100は現在使用する`rt.command`のログ抑制引数に非対応のため、上表には含めていません。YSL-V810はRev.1.03.01からAPI条件を満たす参考環境として記録していますが、今回の17機種・提供環境には含めていません。

## 表の更新方法

機種・最低ファームウェア・動作確認状況はこのページでまとめて管理し、READMEと検証資料から参照します。

動作情報がまだない機種の公開表記は「情報をお待ちしております」に統一します。内部の検証記録では未確認として管理し、報告が届いたら確認された版と結果を追記します。

新たな結果は、機種、ファームウェアRev.、スクリプトの版（独自修正があればその内容）、確認日、試験内容、成功・失敗を組にして記録します。LuaとLuaSocketの版も分かれば記録します。確認できなかった項目は「未確認」とし、別の版の成功結果で置き換えません。詳細な試験記録は[検証資料](validation.md)または該当Releaseの説明へ追加します。

最低ファームウェアを変更する際は、必要APIの変更と公式の導入版を確認します。API互換性、設定解析への対応、実機での動作確認を分けて更新します。
