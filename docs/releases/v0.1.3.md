# v0.1.3 — キャッシュ判定・TCP半閉鎖・DNSクラス制限の修正

v0.1.2で確認・公表した3点を修正しました。既存版をご利用の場合は、対象スクリプトを停止してから添付の`rtx-dns.lua`へ更新してください。

RTX内蔵DNSをTCPで補完し、大きなDNS応答をクライアントへ返せるようにするスクリプトです。配布LuaをそのままRTXへ転送でき、追加ライブラリ・手編集・手元でのビルドは不要です。

## 修正内容

| 項目 | v0.1.2で確認した問題 | v0.1.3の動作 |
|---|---|---|
| キャッシュ対象の判定 | CNAMEと、問い合わせに無関係な名前のAレコードなどが含まれると、必要な回答がない応答を保存する場合がありました。 | 問い合わせ名からCNAMEをたどり、その名前または到達先に要求された種類・クラスの回答がある場合だけ保存します。無関係な回答だけの場合や、必要な回答へ到達できない・CNAMEが矛盾する場合は保存しません。 |
| 複数要求後のTCP半閉鎖 | 同じTCP接続で5件以上の要求をまとめて送り、直後にクライアントの送信側だけを閉じると、応答を返さず接続が閉じる場合がありました。 | 受信済みの完全な要求を順に処理し、応答を送ってから接続を閉じます。最後に不完全な要求が残った場合も、それより前の完全な要求と応答は処理します。 |
| DNSクラスの制限 | INクラスを対象とする説明に反し、CHクラスも上流へ転送していました。 | IN以外のクラスにはFORMERR（RCODE 1）を返し、キャッシュ・内蔵DNS・上流DNSへ渡しません。 |

キャッシュ判定では、回答の並び順、名前の大文字小文字、DNS圧縮を考慮します。通常のA・AAAA・TXT等や、正しく完結するCNAMEの回答は引き続き保存できます。キャッシュ対象外でも、中継時の検査を通る応答はその問い合わせへの回答として転送します。

TCP半閉鎖後にも、送信元IPごとの問い合わせ枠、同時処理数、問い合わせ・書き込みの期限を適用します。制限を超える要求を無条件に処理する変更ではありません。

今回のキャッシュの問題は、問い合わせID・質問などが正しく対応する上流応答の保存判定です。別の名前・DNS選択規則のキャッシュ書き換えや、送信元アクセス制限の回避は確認していません。[v0.1.2の問題の記録](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.3/docs/known-issues.md)

## 既定設定

TCP/53での自動設定、PP・DHCP取得DNSの30秒更新、内蔵UDP DNSへのローカル名の委譲は継続します。既定の保護設定は変更していません。

- 同じ送信元IPからのTCP接続は4本、問い合わせは平均20件/秒・バースト40件。
- 全体ではクライアント32接続、未完了問い合わせ32件。1接続あたり4件を並行処理。
- キャッシュは256件・本文合計1MiB・TTL管理フィールド合計4,096個。

20件/秒は機器の限界性能ではなく、送信元IPごとの保護設定です。これらはLuaのTCP問い合わせに適用し、内蔵DNSのUDP問い合わせには適用しません。

## 検証結果

**RTX830 Rev.15.02.33とRTX1210 Rev.14.01.42で、修正後の実機試験各24ケースが成功しました。** 両機種は整数版Lua 5.1.5（機能1.08）です。

- 3不具合の再試験と、アクセス制限、送信元IPごとの制限、不完全な要求のタイムアウト、不一致の上流応答の拒否を確認しました。
- 両機種の整数版Luaで、問題の応答が保存されず、経過時間を3,599秒として照合してもキャッシュから取得できないことを確認しました。回答の並び順を変えた正常なCNAME応答は保存できました。
- ホスト上では8単体スイート計3,743チェック、キャッシュメモリ719チェック（合計4,462）、リレー60ケース、Python17テストが成功しました。
- 追加の入力検査106,592入力・440,911回の関数呼び出しでは、未処理例外は0件でした。圧縮ポインター16,384通り、キャッシュ20,000操作、DNS選択757チェック、リレー保護17ケースも検査しました。

最終配布候補の実機確認では、両機種で取得内容の長さ142,901バイトとAdler-32を照合した後、整数版Luaでの構文・自動設定・TCP/53起動を確認しました。A・AAAA・大型TXT・ローカルCNAMEとA・CHクラスの5問い合わせずつ、計10件が期待どおりの結果となりました。大型TXTは4,575バイト・58回答、CHクラスは12バイトのFORMERRでした。

この確認では旧版のTCP/53を停止してから候補を一時起動し、終了後に元のファイルから旧版を再起動して正常応答を確認しました。試験用TCP/53053の閉鎖、既存ファイルの長さ・Adler-32、および表示日時行を除いた稼働configの指紋が試験前と一致することも確認しました。

### 短時間負荷

両機種とも、配布版と同じ送信元IP制限（4接続・20クエリ/秒・バースト40件）で、512バイト・10クエリ/秒を45秒（450件）、65,535バイト・5クエリ/秒を45秒（225件）、すべて正常受信しました。

さらに、同じソースの試験設定で送信元IPごとの上限だけを32接続・1,000クエリ/秒・バースト1,000件へ変更し、以下を測定しました。**配布版の既定値は変更していません。**

| 条件 | RTX830 | RTX1210 |
|---|---|---|
| 512バイト・100クエリ/秒・180秒 | 18,000 / 18,000件成功、p95 22.529 ms | 18,000 / 18,000件成功、p95 30.301 ms |
| 65,535バイト・20クエリ/秒・60秒 | 1,200 / 1,200件成功、p95 124.348 ms | 1,200 / 1,200件成功、p95 134.497 ms |

上流はLAN内の合成DNSサーバーで、キャッシュヒットは0件です。性能確認の計19,200件を各機種1本の上流TCP接続で処理し、通信エラー・負荷生成側の取りこぼしは0件でした。CPUの観測最大値はRTX830で19%、RTX1210で56%でした。CPUは不定間隔で取得した5秒平均で、瞬間ピークではありません。既存のルーター処理・常設スクリプト・試験用スクリプトを合わせた装置の値です。

これは最大性能・同時接続容量の探索や1時間の試験ではありません。応答時間の全指標、CPUの採取数・間隔、メモリ使用率は[検証条件と結果](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.3/docs/validation.md)に記載しています。

RTX1300 Rev.23.00.19については、協力者からv0.1.2の`rtx-dns.lua`での動作確認報告をいただいています。Luaのバージョンと具体的な試験項目は未確認です。v0.1.3の実機検証には含めていません。RTX810は未検証です。ルーターの実再起動、強制的なVRRP切り替え、この版の長時間負荷試験は実施していません。[検証条件と最新の動作確認情報](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/main/docs/validation.md)

## インストール・更新

USBメモリやmicroSDカード、SFTP等でインストールします。以下はUSBメモリを使う例です。

1. ReleaseのAssetsから`rtx-dns.lua`と`SHA256SUMS`をダウンロードします。転送前のSHA-256を確認し、LuaファイルをUSBメモリのルートへ保存します。
2. RTXへUSBメモリを接続します。管理者コンソールで`show file list /`を実行し、`/lua`がない場合だけ`make directory /lua`で作成します。
3. **更新時は、コピーする前に対象スクリプトを停止します。** 初回インストールでは停止操作は不要です。

```text
terminate lua file /lua/rtx-dns.lua
show status lua running
```

対象の停止を確認し、既存ファイルを別名で退避してから入れ替えます。次のコマンドは1行ずつ実行し、それぞれの終了を確認してください。

```text
copy usb1:/rtx-dns.lua /lua/rtx-dns.lua
luac -p /lua/rtx-dns.lua
```

構文エラーがなければ、別のコマンドとして起動します。

```text
lua /lua/rtx-dns.lua
show status lua running
show log
```

対象ファイルが動作中で、ログに`DNSRELAY`の起動記録があることを確認します。利用端末から通常の問い合わせと大きなTXT等のTCP問い合わせを行い、応答を確認してください。同じファイルを重複起動しないでください。

起動時にRTXの`dns host`、`ip host`・`dns static`、`dns server select`・`dns server`・`dns server pp`・`dns server dhcp`を読み取ります。`dns service off`など、サービスを開始できない設定では起動を中止します。

### RTX起動時の自動実行

新規導入時は、`100`を未使用のスケジュール番号に置き換えて登録します。**既存版からの更新では、登録済みの起動スケジュールをそのまま使えます。**

```text
schedule at 100 startup * lua /lua/rtx-dns.lua
save
```

手動起動済みなら、そのまま利用できます。まだ起動していない場合は`lua /lua/rtx-dns.lua`で開始するか、自動起動設定を保存してRTX本体を再起動します。更新のためにRTX本体を再起動する必要はありません。[詳しい導入手順](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.3/docs/install.md)

### 設定変更後の再起動

`dns host`、DNSサーバ設定・選択規則、`dns service`、簡易DNS登録名、対象インターフェースのIP等を変更したら、上記の停止・確認・起動手順でLuaを再起動してください。30秒更新の対象はPP・DHCPの取得情報と必要なPP接続状態で、configそのものではありません。同じ設定のまま取得DNSが変わった場合は、再起動不要です。
