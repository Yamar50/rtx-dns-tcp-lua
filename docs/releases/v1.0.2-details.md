# v1.0.2の変更点と検証範囲

[調査の経緯とインストール手順](v1.0.2.md)

新しい接続を最初の1件も受け付けられなかった場合は、システムログに `DNSRELAY TCP accept first wait` を記録します。同じ詳細ログは1分に1回までとし、統計の `accept_first_waits` に発生回数を累積します。1件以上を受け付けた後に接続待ちの列が空になるのは通常の動作です。

RTX830 Rev.15.02.33で観測した高負荷は、UDP待受も備えた開発版での結果です。RTX1210では開発版で空のTCP受付を想定し、既存接続への回答と新規受付の再開を確認しました。公開用のTCP版ではローカルの自動試験で、正常な受付、空振り後の受付再開、既存接続の継続、詳細ログの頻度制限を確認しました。TCPで同じ現象が自然に発生する頻度は分かっていません。
