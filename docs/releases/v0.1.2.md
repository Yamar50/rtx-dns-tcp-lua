# v0.1.2 — PP・DHCP取得DNSへの対応とDNS選択処理の修正

## 既知の問題（2026-09-23追記）

RTX830 Rev.15.02.33とRTX1210 Rev.14.01.42で確認した以下の3点は、**v0.1.3で修正しました。** 以下はv0.1.2での問題の記録です。[修正内容と更新手順](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.3/docs/releases/v0.1.3.md)

| 項目 | 発生条件と影響 |
|---|---|
| キャッシュ対象の判定 | CNAMEと無関係な名前のAレコードなどを含む応答を、正の応答と誤認して保存し、必要な回答がない応答を再利用する場合があります。 |
| 複数要求後のTCP半閉鎖 | 同じTCP接続で5件以上の要求をまとめて送り、直後にクライアントの送信側だけを閉じると、応答を返さず接続が閉じる場合があります。 |
| DNSクラスの制限 | INクラスを対象とする説明に反し、CHクラスの問い合わせも上流へ転送します。送信元IPのアクセス制限は適用されます。 |

キャッシュの問題は、問い合わせID・質問などが正しく対応する上流応答の保存判定です。別の名前・DNS選択規則のキャッシュ書き換えや、送信元のアクセス制限の回避は確認していません。[既知の問題の詳細と対応状況](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/main/docs/known-issues.md)

## 主な修正点

- フレッツ光などでppインターフェイスを使う環境に対応しました。
- DNSサーバアドレスをDHCPから取得する環境に対応しました。
- dns server selectの解析処理の不具合を修正しました。

RTX内蔵DNSをTCPで補完し、大きなDNS応答をクライアントへ返せるようにするスクリプトです。添付の`rtx-dns.lua`をそのままRTXへ転送して使えます。追加ライブラリ・Luaファイルの手編集・手元でのビルドは不要です。

この版では、`dns server pp 1`や`dns server dhcp lan2`のように、接続先からDNSサーバアドレスを取得する設定に対応しました。`dns service fallback on/off`も受け入れます。PP・DHCPの取得情報は30秒ごとに更新します。

## 変更内容

| 項目 | v0.1.2の動作 |
|---|---|
| DNSサービス設定 | `dns service fallback on/off`を受け入れ、これだけで起動を停止しません。`dns service recursive`で開始し、`off`なら起動を中止します。 |
| PP取得DNS | 指定PPの接続状態とIPCPで通知されたDNSアドレスを読み取ります。切断前の古い表示を取得済みと誤認しません。 |
| DHCP取得DNS | 設定された取得元に対応付けられるDNSアドレスを使用します。複数IPv4インターフェースの共通DNS情報を各インターフェースの取得値として流用しません。 |
| 定期更新 | 起動時と30秒ごとに、PP・DHCPの取得結果と必要なPP接続状態を確認します。configそのものの変更は再起動で反映します。 |
| 設定の併記 | 固定DNS、PP、DHCPを別々に保持し、併記を重複エラーにしません。 |
| 選択順序 | `dns server select`を小さい番号から評価します。通信失敗を理由に後続select行へ切り替えません。通常設定は固定DNS、PP、DHCPの優先順です。 |
| selectの取得方法 | 固定IP・PP・DHCP・rejectを区別して解析し、取得DNSと行内の代替DNSを別々に保持します。 |
| selectの条件 | レコード種別、問い合わせ名、IPv4送信元、`restrict pp`を評価します。type省略時はAです。 |
| PTRの拒否 | `reject ptr`をIPv4アドレス・プレフィックスで照合し、一致する問い合わせを破棄します。 |
| AAAAフィルター | `dns service aaaa filter on`に対応。外部へのAAAA問い合わせの応答からAAAAと対応するRRSIGを除去し、CNAMEなどを保持します。加工した応答のADを解除し、キャッシュには保存しません。 |
| 一時的な取得失敗 | 明確なDNS未取得と、状態の読み取り失敗・取得元不明を区別します。取得失敗だけでスクリプト全体を停止せず、該当する問い合わせにSERVFAILを返します。 |
| 未対応上流・構文 | 規則を無条件に読み飛ばしません。条件を判定できる場合は該当する問い合わせだけをSERVFAILとし、判定不能な部分はその規則番号で該当しうる問い合わせの転送を止めます。 |
| 接続・キャッシュ | 実際に使う転送先・選択条件が変わったら、全上流接続とキャッシュを破棄し、処理中の問い合わせをSERVFAILで終了します。古い遅延応答を新しいキャッシュへ登録しません。 |

### DNSが未取得の場合

- 一致したselect行のPP・DHCPが明確にDNS未取得で、行内に代替IPがあれば、そのIPを使用します。
- 代替IPがない場合、DHCP未取得は通常のDNS設定へ移り、PP未取得はSERVFAILを返します。後続select行の再検索はしません。
- 通常のDNS設定の優先順は接続障害時の切り替え順ではありません。通常設定のPPが未取得でも、通常設定のDHCPへ切り替えることはありません。
- 取得元不明、状態の読み取り失敗、IPv6のみの上流は「未取得」と区別し、別のDNSへ推測で切り替えません。

RTX1210 Rev.14.01.42の内蔵DNSでは、DHCP未取得時に行内の代替IPより通常の固定DNSを使うケースがありました。本スクリプトは、行内の明示的な代替IPを使う公式マニュアルの仕様に合わせています。[選択規則と例外時の詳細](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.2/docs/dns-policy.md)

### 対応範囲

- **通信はIPv4のTCP/53です。** AAAAレコードもIPv4上流へ問い合わせできます。IPv6接続・DoT・DoH・NAT46変換は含みません。
- 複数のIPv4 DHCP取得元があり、DNSアドレスを各インターフェースへ対応付けられない場合は、該当する問い合わせにSERVFAILを返します。DHCPv6のclient情報の解析はありますが、IPv6だけの上流への通信には対応しません。
- 簡易DNS登録名は従来どおり内蔵UDP DNSへ渡します。AAAAフィルターはQTYPE=AAAAを対象とし、ANY応答全体からAAAAを除去する機能ではありません。安全に加工できない応答は、その問い合わせだけSERVFAILにします。
- 重複規則番号、壊れた入力、起動時の上限超過、アクセス許可を確定できない設定では起動を中止します。

## 動作確認

**開発時の実機検証はRTX830 Rev.15.02.33とRTX1210 Rev.14.01.42で行いました。RTX810は未検証です。**

追記（2026-09-23）：**RTX1300 Rev.23.00.19については、協力者からv0.1.2の`rtx-dns.lua`での動作確認報告をいただいています。** [最新の動作確認一覧](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/main/docs/validation.md#実機)

- RTX830・RTX1210・PP接続を使用する別のRTX830の3台で、実際に取得したDNSへのTCP転送を検証しました。
- 一時試験で状態読み取り失敗を注入し、SERVFAIL、無関係な固定規則の継続、次回更新での復帰、古い接続・キャッシュの破棄を確認しました。PPの実切断やWAN断を発生させた試験ではありません。
- 配布ファイルと同一のLuaを計6台へ常設配備し、全台でファイル一致・構文・起動を確認しました。LAN側5台へのA・AAAA・大型TXT・簡易DNS登録名の20問い合わせ、VRRP仮想IP 5個への15問い合わせがすべて成功しました。PP設定のある機器でも、許可範囲内からA・AAAA・大型TXTの応答と継続稼働を確認しました。
- ローカルでは単体検査3,619項目、キャッシュメモリ検査719項目（計4,338項目）、リレー53ケース、Python17テストが成功しました。

実機試験では上流TCP接続のタイムアウトを1件観測し、SERVFAILを返すことを確認しました。当該機器の再試験は15件すべて成功しています。実機の再起動、強制的なVRRP切り替え、この版の長時間負荷試験は実施していません。[検証条件と結果](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.2/docs/validation.md)

### 秒間クエリ数の参考値

| RTX830での過去の測定条件 | 実測結果 |
|---|---|
| 512バイト応答 | 100クエリ/秒を1時間、360,000件成功 |
| 65,535バイト応答 | 30クエリ/秒を45秒、1,350件成功 |

`dns server select`対応前の実装を、LAN内の合成上流DNS・キャッシュなし・上流TCP接続再利用で測定した値です。v0.1.2で同条件の長時間負荷試験は再実施していません。v0.1.2の検証ではRTX1210の秒間クエリ数は未測定でした。v0.1.3では両機種で短時間負荷試験を実施しています。[最新の測定条件と結果](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/main/docs/validation.md)

256件キャッシュ、上流TCP接続再利用、送信元IPごとのTCP接続4本・平均20問い合わせ/秒・バースト40件の制限は維持しています。20件/秒は機器の限界性能ではなく、TCP問い合わせに対する既定の保護設定です。

## インストール・更新

USBメモリやmicroSDカード、SFTP等でインストールします。

### 例）USBメモリを使用する場合

1. ReleaseのAssetsから`rtx-dns.lua`と`SHA256SUMS`をダウンロードします。転送前のSHA-256を確認し、LuaファイルをUSBメモリのルートへ保存します。
2. RTXへUSBメモリを接続し、管理者コンソールで`show file list /`を実行します。`/lua`がない場合だけ`make directory /lua`で作成します。
3. **既存版を更新する場合は、コピーする前に対象スクリプトを停止します。** 初回インストールなら、この停止操作は不要です。

```text
terminate lua file /lua/rtx-dns.lua
show status lua running
```

対象の停止を確認し、既存ファイルを別名で退避してから入れ替えます。以下は1行ずつ実行し、各コマンドの終了を確認してください。

```text
copy usb1:/rtx-dns.lua /lua/rtx-dns.lua
luac -p /lua/rtx-dns.lua
```

構文エラーがなければ、別のコマンドとして起動します。

```text
lua /lua/rtx-dns.lua
show status lua running
```

起動時にRTXの`dns host`、`ip host`・`dns static`、`dns server select`・`dns server`・`dns server pp`・`dns server dhcp`を読み取り、自動設定します。同じファイルを重複起動しないでください。

### RTX起動時の自動実行

新規導入時は、`100`を未使用のスケジュール番号に置き換えて登録します。**既存版からの更新では、登録済みの起動スケジュールをそのまま使えます。**

```text
schedule at 100 startup * lua /lua/rtx-dns.lua
save
```

手動起動済みならそのまま利用できます。まだ起動していない場合は、`lua /lua/rtx-dns.lua`で開始するか、自動起動設定を保存してRTX本体を再起動してください。[詳しい導入手順](https://github.com/Yamar50/rtx-dns-tcp-lua/blob/v0.1.2/docs/install.md)

## 設定変更後の再起動

**`dns host`、DNSサーバ設定・選択規則、`dns service`、簡易DNSの登録名、対象インターフェースのIPなどを変更したら、Luaスクリプトを再起動してください。**

```text
terminate lua file /lua/rtx-dns.lua
show status lua running
```

対象が停止したことを確認してから起動します。

```text
lua /lua/rtx-dns.lua
```

例えば`dns host`へ別セグメントの許可を追加しても、再起動まではLua側に古い許可範囲が残り、TCP接続を切断する場合があります。30秒更新の対象はPP・DHCPの取得情報と必要なPP接続状態であり、configそのものではありません。同じ設定のまま取得DNSが変わった場合は再起動不要です。
