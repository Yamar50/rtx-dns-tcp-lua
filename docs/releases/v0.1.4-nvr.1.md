# NVR510試験版：ONUインターフェースのDNS設定に対応

**NVR510の`onu1`を使うDNS設定を読み取れるようにした試験用の`nvr-dns.lua`です。NVR510実機での動作確認は、これから行います。** 安定版は引き続きv0.1.4です。

NVR510で報告された`DNSRELAY startup failed DNS policy line 190: invalid dynamic DNS source`について、`dns server dhcp onu1`または`dns server select ... dhcp onu1 ...`が原因と仮定して修正しました。報告元の該当設定行はまだ未確認です。`line 190`は、Luaファイルではなく、起動時に取得した`show config`出力の行番号です。

報告対象機のファームウェアは、利用者からの情報により **NVR510 Rev.15.01.26（Fri Aug 23 10:36:30 2024）** と確認しました。試験版での動作確認結果は、引き続き報告待ちです。

## 変更内容

- `dns server dhcp onu1`と`dns server select ... dhcp onu1 ...`を受け付けます。
- ONUのDHCP設定とDHCP状態表示を認識し、取得したDNSサーバーを上流選択に使用します。取得情報は従来どおり30秒ごとに確認します。
- `dns host onu1`を明示した場合、ONUに設定された静的IPv4アドレスからアクセス許可範囲を求めます。プライマリ・セカンダリアドレスに対応します。
- IPv6アドレスのスコープ識別子`%onu1`を設定・状態情報として認識します。**IPv6で上流DNSへ接続する機能を追加したものではありません。**

キャッシュ、接続・問い合わせ数制限、送信期限、TCP中継処理はv0.1.4と同じです。Luaファイルの編集は不要で、ルーターの設定を起動時に読み取ります。

## 確認範囲と制限

- ローカルのLua 5.4.7で、既存Luaテスト10本と追加ONUテスト272チェックが成功しました。Pythonの既存テスト17件も成功しています。追加テストではONUのDNS選択・DHCP状態の更新・アクセス許可・不正なインターフェース名の拒否を確認しました。状態表示のテストデータは合成データであり、NVR510実機から取得したものではありません。
- NVR510実機での起動、TCP応答、状態表示の読み取り、性能は未検証です。
- 上流DNSへの接続はIPv4のみです。取得したDNSがIPv6アドレスだけの場合、該当する問い合わせにはSERVFAILを返します。
- 試験版では`dns host lan`の許可範囲をONUへ拡大しません。NVR510内蔵DNSでこの指定がONUを含むかは未確認のため、従来のスクリプトの許可範囲を維持します。ONU側からの利用を許可するには、必要な`onu1`またはIPv4範囲を明示してください。これは利用許可側の話であり、上流DNSをONU経由で使うために`dns host onu1`へ変更する必要はありません。
- `dns host onu1`を使う場合も、アクセス許可範囲の自動生成はconfigの静的IPv4アドレスが対象です。ONUのIPv4アドレスをDHCPで取得する場合、その範囲を推測して許可する処理は追加していません。
- configの変更後はスクリプトの再起動が必要です。config自体の自動再読み込みは行いません。

## ダウンロードと試験手順

Assetsから`nvr-dns.lua`と`SHA256SUMS`をダウンロードし、SHA-256が一致することを確認してください。USBメモリやmicroSDカード、SFTP等で転送できます。以下はUSBメモリを使う例です。

1. 同じルーターで旧`rtx-dns.lua`や試験用`nvr-dns.lua`が動作している場合は、先に該当ファイルだけを停止します。両方を同時に起動しないでください。

```text
show status lua running
terminate lua file /lua/rtx-dns.lua
terminate lua file /lua/nvr-dns.lua
show status lua running
```

`terminate`は上記で実行中と確認した対象にだけ実行します。別の場所に置いている場合は、そのパスを指定してください。旧版のファイルは残しておきます。

2. `/lua`ディレクトリがない場合だけ`make directory /lua`で作成し、試験版をコピーします。各コマンドは終了を確認してから次へ進めます。

```text
copy usb1:/nvr-dns.lua /lua/nvr-dns.lua
luac -p /lua/nvr-dns.lua
lua /lua/nvr-dns.lua
show status lua running
show log
```

3. 端末からルーターへTCPで問い合わせます。`192.0.2.1`は説明用のアドレスなので、実際のNVR510のIPv4アドレスに置き換えてください。

```sh
dig @192.0.2.1 google.com A +tcp +time=5 +tries=1
dig @192.0.2.1 microsoft.com TXT +time=5 +tries=1
```

簡易DNSのレコードを登録している場合は、その名前でも`+tcp`を付けて確認してください。起動エラーが消えることと、実際に応答が返ることの両方を確認します。

初回試験は手動起動で行います。既存の自動起動設定は変更せず、この試験用ファイルの自動起動もまだ登録しません。

## 試験終了・切り戻し

```text
terminate lua file /lua/nvr-dns.lua
show status lua running
```

旧版が正常動作していた環境に戻す場合は、試験版の停止後に旧版を起動します。

```text
lua /lua/rtx-dns.lua
```

旧版が今回の設定解析エラーで起動できなかった環境では、停止した状態に戻すだけでかまいません。このスクリプトの起動・停止は、ルーターのconfigや内蔵UDP DNSを変更しません。

## 結果を知らせていただく際の情報

- NVR510のファームウェアRev.と、使用した試験版名`v0.1.4-nvr.1`。
- `show status lua running`の対象行と`DNSRELAY`の起動・エラーログ。
- TCPでの問い合わせ結果。
- 上流DNSの取得に失敗する場合は、関係するDNS/DHCP設定行と`show status dhcpc`／`show status ipv6 dhcp`の該当部分。

認証情報を含むconfig全体は不要です。公開する場合は、個人情報や環境固有の情報を伏せてください。
