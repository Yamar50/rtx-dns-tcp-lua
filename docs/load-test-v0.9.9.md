# v0.9.9 実機負荷試験

**負荷試験中にYAMAHA RTX830の再起動を確認しました。v0.9.9候補版の公開は保留しています。**

監視が途切れた後、ルータの起動時刻が変わり、起動履歴に`Rebooted by Data Abort(4)`が記録されたことを確認しました。根本原因と試験負荷との関係は調査中です。完了した段階と中断した段階、再起動後の追加比較を分けて記載します。

- YAMAHA RTX830の65,535 bytes・予定160 QPSは、最終結果を取得できず未完了です。
- YAMAHA RTX830の再起動後の起動時刻：2026/09/23 21:55:29 +09:00。

**初回の予定12段階のうち11段階が完了し、1段階は再起動に伴い中断しました。負荷試験は終了しています。原因調査は継続中です。**

## 試験したファイル

- 対象版：`v0.9.9` 候補の `rtx-dns.lua`。
- ファイルサイズ：150,764 bytes。
- ソースコミット：`779e947`。
- SHA-256：`c49daef597e0e56e0fb996750ddc4adca8c30e4927b0be3477d34f21e83ad453`。

実際の試験では、このファイルの全モジュールをRAM上で使用し、待受先・合成上流などの試験用設定だけを変更しました。常用ファイルの置換による試験ではありません。

**送信元制限を緩和した容量測定です。公開版の通常設定（1送信元4接続・20 QPS・バースト40）で、この表のQPSを許可するという意味ではありません。** 通常制限が働くことは、両機の別ポートによる32項目の機能回帰試験で確認しました。この制限はLuaが扱うTCP問い合わせに適用され、内蔵DNSのUDP処理やLuaに届く前のTCP処理を保護するものではありません。

過去のv0.1.3試験は複数送信元を使うなど条件が異なります。今回の結果を、そのまま版ごとの性能改善・悪化の比較には使用できません。

## 各段階の結果

「予定QPS」と「計画枠」は負荷生成器の投入予定です。「開始」はTCP接続を試みた件数、「DNS送信」はDNS要求を書き出した件数です。生成器の同時実行上限により開始できなかった枠は「未開始」に数えます。予定した全件がルータへ到達したとは限りません。

「成功QPS」は全バイト検証を通った正常応答件数を、**投入開始から終了後の完了待ちまで含めた実測時間**で割った値です。「p95」は成功した要求の95パーセンタイル遅延で、timeoutなどの失敗要求を含みません。CPU欄は **CPU0 / 全体** の順で、観測した5秒平均の最大値（%）です。YAMAHA RTX1210ではCPU0を独立表示していません。

## 結果の読み方と範囲

- 通信エラーやtimeoutには、ルータの受付・TCP接続・応答待ちに加え、負荷生成側やネットワークの影響も含まれます。この件数だけで原因をルータCPUに断定できません。
- 未開始の枠はルータが返した失敗ではありません。負荷生成器が同時128要求に達し、新しい処理を開始できなかった枠です。
- 1,000 QPSの段階では、試験用に緩和した送信元制限も1,000 QPSです。全体の能力と送信元制限を区別するにはLua側のカウンタ確認も必要です。
- 応答は合成TXTで、通常の外部DNS遅延を含みません。同じサイズでも、大量の小さなレコードを含む応答では処理時間が異なります。
- 静的上流の試験であり、PP/DHCP再接続や全DNS選択ルールの動作を負荷下で網羅したものではありません。
- 常用DNSとの並行稼働を含む短期試験です。長期連続稼働、メモリリークの不存在、他機種の性能はこの結果だけでは判断できません。

## 終了後の確認

- 両機の試験用Lua、合成DNS、転送用HTTP、監視プロセスを終了しました。TCP/53053と試験用サーバの待受が閉じていることを確認しました。
- 保存済みconfigと常用`rtx-dns.lua`のサイズ・チェックサムは、試験前後の確認で一致しました。試験ではconfig変更・保存・常用ファイルの置換を行っていません。実行中configの出力は取得日時のヘッダーが変わるため、生出力のチェックサムは一致比較に使用していません。
- 常用v0.1.4のTCP/53に対し、外部A・AAAA・大きなTXT、登録済みA・別名A・CNAME・PTR、select対象TXTの8項目が両機ですべて成功しました。
- RTX830の常用Luaは本体再起動に伴い自動起動しました。RTX1210の常用Luaの起動日時は変わっていません。
- 終了後の本体CPU使用率はRTX830が0%、RTX1210が1%、メモリ使用率は42%・19%でした。
- RTX1210のLAN1受信オーバーフローは試験前後とも1,299で、増加はありませんでした。RTX830は本体再起動でカウンタがリセットされているため、試験全体の差分を判定できません。

再起動前の最後の本体メモリ使用率は44%（21:54:38）、最後に取得できた試験用Luaのメモリは1,137 KiBでした。取得記録にメモリが増え続けて枯渇した兆候はありません。ただし、最後の本体計測から21:55:29の再起動まで約51秒間は状態を取得できず、その間の変化は未確認です。

今回の各1回の追加比較では、旧版・同じ候補版とも再起動を再現しませんでした。**この結果だけで初回の問題を否定したり、修正済みと判断したりはできません。** 新版差分が原因か、旧新版に共通する処理・ルータの状態が原因かは未確定です。公開保留を継続します。
