# DNS設定の自動再読込

[インストールと機能](../README.md) · [技術資料一覧](README.md)

ソースコード・テスト・ドキュメントはすべてOpenAI Codexで生成した。

**v1.0.0では、DNS関連の設定変更後にLuaスクリプトやルーターを手動で再起動する必要がなくなりました。** 配布ファイルは起動時と約30秒ごとに稼働中のconfigを確認し、変更を同じLuaタスク内で反映します。配布ファイルの編集は不要です。

## 読み直す設定

| 設定 | 反映する内容 |
|---|---|
| `dns server`・`dns server select` | 上流DNS、選択条件、EDNS、拒否規則など |
| `dns host` | 利用を許可する端末・LAN |
| `ip host`・`dns static` | 内蔵DNSへ戻す簡易DNSの登録名 |
| `dns service` | DNS機能の有効・無効、AAAAフィルターなど |
| 関連するインターフェース設定 | IPv4のアドレス・セカンダリーアドレス、PPのリモートアドレス、DHCPv6の取得元判定に使う設定 |

設定全体を取得した後、このスクリプトが使用する行を抜き出して比較します。空白の違いやコメントは比較対象から除きます。無関係な設定変更だけで接続とキャッシュを初期化しません。DNSの選択順や対応する構文は[DNS設定の選択と定期更新](dns-policy.md)を参照してください。

PP・DHCPで取得したDNSアドレスやPP接続状態も、従来どおり30秒ごとに確認します。設定変更がなくても、取得DNSが変われば古い上流接続とキャッシュを破棄します。

## 変更を反映するとき

| 状態 | 動作 |
|---|---|
| 関連する設定に変更なし | 接続とキャッシュを維持して中継を継続 |
| 有効な設定へ変更 | 古いクライアント・上流接続を閉じ、キャッシュを破棄して新しい設定で待受を開始 |
| アクセス許可を縮小 | 次回の反映時に既存クライアントも切断し、新しい許可範囲で受け付ける |
| `dns service off`・許可端末なし | TCP待受を停止。設定確認は続け、有効な設定に戻れば復帰 |
| 設定取得失敗・初期化できない設定 | 古い設定で応答を続けずTCP待受を停止。約30秒ごとに再試行 |

設定の反映中は、処理中の問い合わせが接続切断などで一時的に失敗することがあります。設定を複数のコマンドで編集中の場合も、途中の状態を読み取ることがあります。正常な設定を読めるようになれば自動で復帰します。

反映は即時ではありません。次回の設定確認までは従来の設定が使われます。設定取得やDNS処理にかかる時間も加わるため、変更から厳密に30秒以内の反映を保証するタイマーではありません。

自動再読込は稼働中のconfigを使用し、ルーターの設定を書き換えたり保存したりしません。変更した設定を次のルーター起動後にも維持するには、通常どおり`save`を実行します。

## 確認と制限

コンソールでは`show status lua running`で対象タスクを確認できます。ただし、DNS無効・許可なし・設定エラーの間も監視タスクは動くため、タスクの存在だけでTCP待受の成功を判定しないでください。実際の名前解決と、`DNSRELOAD`・`DNSRELAY`のログで確認します。[導入後の確認方法](install.md#起動しない名前解決できない場合)

`DNSRELOAD`の`generation`は初期化して待受を開始した回数です。監視側の`failures`にはDNS無効や許可なしによる初期化見送り・再試行も含まれ、クライアントのDNS問い合わせ失敗数とは異なります。

設定APIが失敗した場合、空の応答や上限超過などは検出します。一方、APIが成功として返す構文上もっともらしい部分的な設定について、全設定がそろっているかを判定する機能はありません。

Luaファイル内のコードや設定値を変更した場合、および監視タスク自体が停止した場合は、ファイルの更新・手動起動が必要です。v0.9.9以前はDNS関連のconfig変更後も手動再起動が必要です。[過去のバージョン](releases/history.md)

## 試験結果

RTX1210 Rev.14.01.42で、固定DNS、簡易DNSレコードの追加・変更・削除、選択規則の拒否・転送・削除、アクセス許可の拒否・復帰、DNS機能の停止・復帰、設定不変を検証しました。接続数・問い合わせ数・キャッシュ・タイムアウトの通常制限は維持しています。

| 試験 | 時間・回数 | 結果 |
|---|---|---|
| 短時間の12項目 | 約613秒・580問い合わせ | 想定した結果447件、反映中の結果133件、想定外0件 |
| 設定変更を繰り返す連続試験 | 約141.5時間・467周と次の周の途中・485,141問い合わせ | 想定した結果433,168件、反映中の結果51,973件、想定外0件 |

連続試験のLuaヒープの観測最大値は764KiBでした。DNS無効・アクセス拒否の項目では応答しないことを正しい結果として判定するため、問い合わせ数全体を正常なDNS回答の件数とは扱いません。

当初の7日間を完走した結果ではなく、v1.0.0の公開準備のため約141.5時間で試験を終了した結果です。終了後は元のDNS設定とLua稼働状態への復元、試験用ファイルと一時認証ファイルの削除を確認しました。

この連続試験はv1.0.0に採用した自動再読込処理の試験用ファイルを対象としています。版、ファイルのハッシュ、判定条件、v1.0.0配布ファイル自体の確認との区別は[設定再読込の試験記録](results/config-reload-2026-10-05.md)にまとめています。
