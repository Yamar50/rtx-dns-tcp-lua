## 基本方針

**IPv6専用DNSに対する既存のIPv4 DNSへの切替を除き、`dns server select`の条件判定と問い合わせ先の選択・切替を、内蔵DNSの挙動に合わせます。** 内蔵DNSでは次の規則に進まない状態を、Luaだけが「使えないから次へ」と扱わないことが要件です。

公式仕様と実測に違いがある部分は、取得状態・機種・ファームウェアを分けて確認します。1機種の限定した状態での結果を、全機種に共通する挙動として実装しません。解消していない差は「互換性の未達項目」として残します。

この資料で合わせるのは**どの規則・DNSを選び、どこへ進まないか**です。内蔵DNSへのUDP要求とLuaへのTCP要求では、接続・再送・待ち時間が異なります。Luaの既存の処理期限と、最終失敗時にSERVFAILを返す方針は維持します。内蔵DNSで45秒待っても応答がなかったことを理由に、Luaも45秒無応答にする変更ではありません。

## 用語と公式仕様の基準

| 用語 | この資料での意味 |
|---|---|
| 後続規則 | 番号がより大きい別の`dns server select`規則 |
| 通常DNS | `dns server`等で設定された、select以外のDNS選択先 |
| 行内の代替DNS | `dns server select ... pp/dhcp ...`内に指定する代替IP。公式書式の引数名は`default-server`で、入力するキーワードではない |
| 同じ規則内の再試行 | その規則が持つ別のDNS候補を試すこと。後続規則への切替とは別 |
| DNS未取得 | 状態取得が成功し、DNSがないと確認できた状態。取得失敗・解析不能とは区別する |

規則は番号順に評価し、名前・レコード種別・元クライアント・指定された`restrict pp`を条件にします。`pp peer_num`はDNS取得元、`restrict pp connection-pp`は接続条件の対象で、番号が同じとは限りません。条件不一致なら後続を調べ、一致した規則の応答失敗を理由に再び規則検索を始めません。すべて非一致なら通常DNSを使います。`reject`は拒否として扱います。[公式：dns server select](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/dns/dns_server_select.html)

通常設定の優先順位はselect、固定DNS、PP取得DNS、DHCP取得DNSです。この優先順位と「選んだDNSが無応答だったときの動作」を混同しません。本資料の通常DNSへの遷移の実機確認は、固定の通常DNSがある条件です。通常設定同士の未取得時の切替まで確認したものではありません。[公式：DNSの設定](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/dns/dns_chapter.html)

## 実機結果と現行Luaの差

内蔵DNSの観測はRTX1210 Rev.14.01.42、2026-10-07のものです。PPはLAN内PPTP/IPCPであり、PPPoEの実測ではありません。Lua欄はv1.0.0のソース確認と、実機の状態表示を入力したオフライン再生です。詳細・観測IDは[試験記録](results/native-select-2026-10-07.md)を参照してください。

| 条件 | 内蔵DNSの観測 | v1.0.0の状態／必要な対応 |
|---|---|---|
| 一致した固定IPv4 DNSがSERVFAILまたは無応答（N01） | 後続select・通常DNSを使わなかった | 選択済み規則に限定する現行方針を維持。通信失敗による規則間切替を追加しない |
| PP接続済み・DNS取得済み（N02） | 当該PPのDNSを使用。SERVFAIL・無応答でも後続へ進まなかった | 実際のPPTP接続表示を解析できず状態不明になる。接続表示の対応を修正する |
| PP無効化・切断済み、`restrict pp`あり（N03） | 当該規則を使わず後続selectを使用 | 実際の「回線は現在使用できません」を解析できず状態不明になる。明確な非接続状態を認識する |
| 同じPP状態、`restrict pp`なし（N04） | 後続select・通常DNSへ進まず無応答 | PP切断を理由に暗黙の`restrict`を追加しない。宛先を得られないLua要求は既存方針のSERVFAIL |
| PP接続済み・通知DNSなし（N05） | `restrict`の有無にかかわらず後続・通常DNSを使わなかった | 接続状態とDNS取得状態を別に扱う。行内代替DNSの扱いは下記の追加確認対象 |
| DHCP取得済み、LANリンクダウン後もリースとDNSを保持（N06） | 取得済みDNSを別経路で利用できた | リンクダウンだけで規則を除外しない。今回の複数DHCP環境では現行Luaは取得元不明になるため、取得元対応付けが未達 |
| DHCPのIPリースなし・サーバ検索中、行内代替DNSなし（N07） | 後続selectを使わず通常の固定DNSを使用 | 「サーバ検索中」を解析できず状態不明になる。明確なIP未取得状態として認識する |
| 同じ未取得状態、行内代替DNSあり（N08） | 行内代替DNSも後続selectも使わず通常の固定DNSを使用 | 現行Luaは未取得と認識すると行内代替DNSを優先。取得状態を分けた追加実測後に修正する |

**「条件に一致しなかった」「一致したがDNSを取得していない」「選択したDNSに問い合わせて失敗した」は別の状態です。** 外から見た問い合わせ先だけで、内蔵DNS内部の実装がどの分岐を使ったかまでは断定しません。

## 状態を分離して保持する

実装では、現在の`present / absent / unknown`だけで早い段階からまとめず、少なくとも次の情報を選択判定まで保持する方針です。名称は設計上の区分であり、新APIの確定名ではありません。

| 状態軸 | 必要な区別 |
|---|---|
| 条件用PP | 接続・非接続・取得／解析不能。DNS取得元PPとは独立 |
| DNS取得元PP | 接続状態、IPCP情報の有無、DNS通知あり／なし、表示不明 |
| DHCP | IPリースなし・取得処理中、リースありDNSなし、DNS取得済み、保持中、取得元不明 |
| インターフェース | リンク状態と取得情報の保持状態。リンクダウンからDNS消失を推測しない |
| DNS候補 | IPv4あり、IPv6のみと確定、不正／不明。AAAAという問い合わせタイプとは別 |
| 問い合わせ結果 | 正常応答、DNSエラー応答、接続失敗、無応答。不一致へ書き換えない |

日本語の「PPTPセッションは接続されています」「回線は現在使用できません」「サーバ検索中」を、対象番号や表示全体の整合性とともに認識する必要があります。日本語UTF-8・CP932と英語表示を対象にします。実測していない英語表現を、実機確認済みとは記録しません。矛盾する表示、コマンド失敗、途中で切れた出力を「切断」や「未取得」に変換しません。

複数DHCPインターフェースの共通DNS欄は、指定IFのDNSであることを根拠なく仮定しません。指定IFと取得DNSの対応を確定できる公式情報・取得方法を調べ、複数取得元が異なるDNSを通知する実験で検証します。**現在の曖昧さを理由とするSERVFAILは既知の実装上の制約であり、内蔵DNSとの互換性を達成した扱いにはしません。** 解決前に推測で別のDNSへ転送する変更もしません。

## 評価手順と遷移

| 順序 | 判定 | 処理方針 |
|---|---|---|
| 1 | レコード種別・名前・送信元が不一致 | 後続selectを調べる |
| 2 | `restrict pp N`があり、Nが明確に非接続 | 後続selectを調べる。取得元が固定・PP・DHCPのいずれでも同じ条件 |
| 3 | その規則の判定に必要な条件または取得状態を確定できない | 推測で後続へ送らない。現行のSERVFAILを暫定維持し、互換性の未達項目として記録 |
| 4 | 解釈できる`reject`に一致 | 拒否する。後続select・通常DNSへ送らない |
| 5 | 同じ規則に利用できるIPv4候補あり | その規則を選択する。問い合わせ後の失敗で規則検索を再開しない |
| 6 | DNS候補がIPv6のみと確定 | 下記の既存例外を適用する |
| 7 | 取得DNSがないと確定 | PP／DHCP、IPリースの有無、行内代替DNSを分け、実機で確認した対応表に従う。未確定の組合せは実装前に確認する |
| 8 | 条件不一致またはIPv6専用の例外によってselectを調べ終えた | 通常DNSを選ぶ。利用可能な宛先がなければSERVFAIL |

DHCP未取得時に通常DNSを使うN07は、手順7から通常DNSへ進むケースです。「すべての後続selectを検索する」と同じ処理にしません。行内代替DNSがあるN08まで同じとするかは、次節の確認を終えて決めます。

処理中にDNS設定・取得状態が変化した場合は、v1.0.0の設定／状態更新と接続・キャッシュ破棄の処理と整合させます。内蔵DNSと比べる際は同一状態のスナップショットを使い、約30秒の更新待ちを区別します。更新直前まで古い状態を使用する時間差は記録し、常時・即時に一致すると説明しません。毎クエリで状態コマンドを実行する仕様変更は本資料では決めません。

## 維持するIPv6専用DNSの例外

[既存のIPv4 DNSへの切替仕様](dns-ipv6-fallback.md)を維持します。

1. 設定・条件・取得状態を解釈でき、使えない理由が**DNSのアドレスがIPv6のみ**と確定したselect規則だけを除外する。
2. 条件に合う後続selectを探す。同じ規則にIPv4があれば、そのIPv4を使う。
3. 後続がなければ通常DNSの利用可能なIPv4を使う。それでも問い合わせできなければSERVFAIL。

後続の`restrict`、送信元・名前・タイプ条件、明示拒否は引き続き評価します。途中の状態不明を読み飛ばしません。IPv4 DNSの無応答、SERVFAIL、DNS未取得、NAT46が必要な設定を、この例外へ含めません。通常の固定DNSがIPv6のみだったことを理由に、さらに通常PP・DHCPへ候補を広げる変更も含めません。

## 実装前に確定させる項目

| ID | 未確定項目 | 確認方法・決定条件 |
|---|---|---|
| U01 | 行内代替DNSの適用条件 | PPは未接続／接続済みDNS通知なし、DHCPはIPなし／IPありDNSオプションなしを別々に試す。代替あり／なし、通常DNSあり／なしで送信先を観測する |
| U02 | 複数DHCP取得元とDNSの対応 | 各IFに異なるDNSを通知し、指定IF・取得順・更新・失効を変える。共通欄の先頭を無条件に使う案は採らない |
| U03 | PPPoEと機種・FW差 | RTX830の接続中、RTX1210の非接続・接続処理中の英語表示を採取済み。接続中表記の解析不足を再現。RTX1300の診断ログは状態不明を示すが、稼働Luaの生出力と修正後DNS応答は未確認。状態表示の対応と、内蔵DNSとの選択比較は別途完了させる |
| U04 | 切断後の保持・復帰 | 管理的shutdown、物理切断、自然なリース失効、再接続を分ける。未実施のDHCPリンク復帰ケースを補う |
| U05 | 通常DNSの選択も含む不足条件 | 通常の固定DNSがない構成、PP／DHCPの通常設定、DHCPv6・ONU等は別途確認。1つのLANの結果を全IFへ一括適用しない |

U01は公式の代替DNSの説明と今回の観測に差があるため優先して確認します。現行の「未取得なら常に行内代替DNS」を完成仕様として固定せず、反対に「代替DNSは常に無視」とも決めません。差が機種・FWごとに残る場合は、条件別の互換性範囲を明記してから実装方針を決めます。

## 修正・検証の順序と合格条件

| 順序 | 作業 | 合格条件 |
|---|---|---|
| 1 | 実機表示から状態を読む部分を修正 | N02・N03・N07の採取表示を正しく区別。UTF-8／CP932、対象番号違い、矛盾、欠損、取得失敗を含む回帰試験を通す |
| 2 | U01・U02を追加検証し、未取得状態を分ける | 状態別に選択先を確定できる。根拠のないIF対応付けや後続selectへの迂回がない |
| 3 | 選択処理を修正 | 以下の比較項目で内蔵DNSと選択先が一致する。IPv6例外だけは別の期待値で合格判定 |
| 4 | 更新・既存機能の回帰 | 取得DNS／接続状態／configの変化後、旧接続・キャッシュが誤用されず復帰する。ACL、ローカルDNS、負荷制限も維持 |
| 5 | 実機比較と文書更新 | 修正版の版・SHA256、機種・FW、問い合わせと各上流の送信記録、未確認範囲を保存。修正済みと実機確認済みを区別する |

実機比較では、内蔵DNSへのUDPとLuaへのTCPについて、同じ設定・取得状態・元クライアント・質問を使います。キャッシュを無効化するか毎回未使用名を用い、すべての候補DNSと通常DNSの到達を観測します。最終回答だけで選択先を推測しません。各観測経路に正常応答の対照を置き、無応答と監視失敗を区別します。

必須の比較項目は次のとおりです。

- N01～N08の再現。ただしU01に属する行内代替DNSは、追加検証後に期待値を確定する。
- タイプ省略・A・AAAA・PTR・`any`、名前条件、元クライアント条件、`reject`、非一致時の通常DNS。
- DNS取得元PPと`restrict pp`対象PPが異なる設定。固定DNSにも`restrict pp`がある設定。
- 同じ規則のプライマリ／セカンダリDNSの再試行と、異なるselect規則への切替を別々に確認する。今回の実測だけでは同一規則内の再試行互換性は未検証。
- SERVFAIL以外のREFUSED・NXDOMAIN・NOERRORで回答なしの場合も比較する。これらは今回の実測済みケースには含めず、後続selectへ進む根拠としない。
- IPv6のみ→後続IPv4、IPv6のみ→通常IPv4、IPv4／IPv6混在、途中の拒否／状態不明、IPv4 DNSに対するAAAA要求。
- DHCP取得・再取得・保持・失効、PP接続・切断・再接続、更新の前後と問い合わせ処理中の変更。

2026-10-07の追記時点では英語PPPoEの接続中表記のみ修正候補があり、ホスト上で試験済みです。修正版による実機DNS通信試験と配布物の差し替えは行っていません。既存の起動・停止・制限値や、報告者環境の設定を変更する指示書ではありません。
