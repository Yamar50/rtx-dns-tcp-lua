# 文書の関連付けと更新手順

[開発・検証](development.md) · [技術資料一覧](README.md)

ソースコード・テスト・ドキュメントはすべてOpenAI Codexで生成した。

変更箇所から見直す資料を特定するための正本は、[文書対応表（JSON）](maintenance-map.json)です。GPTも人もこの表から確認先を選び、チャットの履歴に依存せず作業します。作業開始時の参照は、リポジトリの[AGENTS.md](../AGENTS.md)で指定しています。

## 作業の開始と終了

作業前に現在のブランチ・未コミット変更・開始commitを確認し、変更する話題またはファイルから対応表を検索します。

```sh
python3 tools/doc_impact.py --list
python3 tools/doc_impact.py --topic installer-progress
python3 tools/doc_impact.py src/dns_policy.lua
```

検索結果は「変更必須の一覧」ではなく「見直しが必要な一覧」です。`authority`は実装・仕様・根拠の参照先、`review`は現在の説明、`artifacts`は配布物・画像など、`historical`は版や日付を固定した記録、`external`はGitHub上などの別の公開先です。読み直す範囲を絞るため、最初に選ばれたグループだけを読みます。

作業後は実際の差分からもう一度確認します。`<開始commit>`は作業開始時に記録したcommitに置き換えてください。

```sh
python3 tools/doc_impact.py --diff <開始commit>
python3 tools/doc_impact.py --check
```

対応表と検索ツールだけを確認する場合は`make docs-check`を使えます。通常の`make test`にも対応表の検査を含めています。

確認先ごとに`updated`（更新）、`checked-no-change`（確認済み・変更不要、その理由）、`pending`（未完了と理由）を記録します。根拠となる版・commit・試験日・証跡の場所も残します。ローカルにプロジェクト記憶がある場合はそこへ保存し、ない場合は引継ぎに記載します。未完了の公開や確認を「完了」としません。

ツールは参照先の存在と対象ファイルの登録漏れを検査します。文章の意味、実機の状態、Web上の公開内容は自動では検証しません。対応表にない変更は、関連先を調べて表を追加してから進めます。新しい版の導入時には、Release本文の同期対象と、現在の説明・過去の記録の区分も見直します。

## 今回の取りこぼしを防ぐ例

インストーラーの進捗表示を変更したら、実装と生成したインストーラーに加え、`docs/installer.md`の完了表示・カウンター説明・試験の要約を確認します。試験記録へのリンクがあっても、リンク元の説明が古いままなら修正が必要です。

現在の配布版では表示は16件の連番ですが、処理工程と失敗時の`stage`番号は9工程です。過去の9工程表示の試験を「16件で試験した」と書き換えてはいけません。表示変更後の実機確認は、その時点の版・引数・取得経路とともに追記し、現在の手順書はその結果を正確に要約します。将来の表示件数は実装から再確認します。

## 公開先と生成物

- オンラインインストールのコマンドは、確定したインストーラーcommitから`tools/installer_command.py`で生成し、README・手順書・対象Release本文を照合します。画像内のコマンドも確認します。
- GitHub Release本文は対応表の`external_surfaces.github_release_bodies`にあるローカルファイルと照合します。本文だけの変更で配布物・タグ・Pre-releaseなどの設定を変えません。
- 本体、インストーラー、アンインストーラーは別の生成物です。本体を変更していない説明修正で再ビルド・配備を行う必要はありません。
- 過去の試験記録は当時の証拠です。新しい実装で自動的に再検証済みにはなりません。誤記の訂正と新しい試験結果の追加を区別します。
- 既存の版に固定された本体・チェックサム・commit URLを、新版へ黙って置き換えません。公開後は実際の本文と必要な配布物を取得して確認します。

READMEと現行Release本文は「オンラインインストール」と「できるようになること」を中心に短く保ち、詳細は技術資料へリンクします。この保守手順をインストール説明へ展開する必要はありません。
